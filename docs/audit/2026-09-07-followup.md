## Fix first

### N1 — `safeInternalPath()` is bypassable with a tab or newline **[verified]**

`lib/utils/url.ts:32-33`

```ts
if (!raw.startsWith("/")) return null;
if (raw.startsWith("//") || raw.startsWith("/\\")) return null;
```

The guard inspects the first two characters only. The WHATWG URL parser — in
browsers and in Node — strips all ASCII tabs and newlines *before* parsing, so
`/<TAB>/evil.example` passes both checks and then resolves to
`https://evil.example/`. Reproduced against the real function body:

| input | guard | resolves to |
| --- | --- | --- |
| `"//evil.example"` | blocked | — |
| `"/\\evil.example"` | blocked | — |
| `"/\t/evil.example"` | **passed** | `https://evil.example/` |
| `"/\n/evil.example"` | **passed** | `https://evil.example/` |
| `"/\r/evil.example"` | **passed** | `https://evil.example/` |

Attack: `https://cornice/anmelden?next=/%09/evil.example`. `app/anmelden/page.tsx:28`
passes it through, `AnmeldenForm.tsx:20` writes it into the hidden `next` field,
the victim enters credentials, and `signIn()` redirects off-origin
(`lib/actions/auth.ts:71`) — the exact scenario the comment at `auth.ts:63-70`
claims is defeated.

Other sinks: `lib/actions/vehicles.ts:101`, `lib/actions/auth.ts:167`, and
`app/profil/fahrzeuge/neu/page.tsx:14,18` → `BackButton.tsx:13` `router.push()`,
which needs no login at all.

`app/auth/callback/route.ts:26` is **not** affected — it builds `${origin}${next}`,
so the tab variant yields an on-origin path. The flaw is confined to sinks that
use the value as a relative URL.

`lib/utils/url.test.ts:35-39` covers `//evil.example` and `/\evil.example`;
no test in the file contains a control character.

**Fix:** reject any input matching `/[\x00-\x1F\x7F]/` outright, then
require `^\/(?![/\\])`. Add regression tests for `\t`, `\n`, `\r` and `%09`.

*This contradicts the prior audit's headline "No open redirect … was found" —
that conclusion was correct for the classes it tested, and this class was not
among them.*

### N2 — `0045` silently dropped the `zeigt_fahrzeuge` privacy bracket **[verified]**

`supabase/migrations/0045_freie_fahrten_teilen.sql:93-95`

`0038_completion_photo_and_vehicle_privacy_fixes.sql:112-114` deliberately gated
the vehicle columns of `public_fahrten`:

```sql
case when p.zeigt_fahrzeuge or rc.user_id = auth.uid() then v.typ else null end as fahrzeug_typ,
```

`0045` rewrote the view with `create or replace` and left the bracket out:

```sql
v.typ as fahrzeug_typ,
v.marke as fahrzeug_marke,
v.modell as fahrzeug_modell,
```

No later migration restores it (checked across all 75 files). `public_fahrten`
runs with owner rights — no `security_invoker` — and is granted to `anon` and
`authenticated` (`0015:57`), so the RLS policy on `vehicles` never applies.

A user who set `zeigt_fahrzeuge = false` (the default until `0054`) and shares a
ride exposes make, model and type to anyone, signed out included: rendered at
`app/fahrten/[id]/page.tsx:264`, and shipped in full by `lib/feed.ts:27`
(`select("*")`, all 21 columns) into the RSC payload. A direct PostgREST read of
the view returns the same. The visibility switch tells the user the opposite —
and the view's own COMMENT still asserts the bracket is there.

**Fix:** new migration restoring the `case when` from `0038 D`, carrying the
comment forward so the next `create or replace` cannot lose it silently.

This also removes the mitigation the prior audit relied on when rating F8 /
security #8 (unchecked `fahrzeug_id`, still open): `docs/audit/security.md:160`
argues the impact is bounded because `public_fahrten` gates vehicle columns on
the owner's flag. It has not done so since `0045`. Attaching a stranger's
vehicle UUID to your own public ride now exposes their vehicle regardless of
either party's setting.

### N3 — Two more duplicate migration prefixes, and the un-applied halves are the security fixes **[verified]**

`supabase/migrations/README.md:62` states there are **four** duplicate prefixes
and lists `0034`, `0041`, `0053`, `0054`. There are **six** across 75 files:

| prefix | applied | **not** applied |
| --- | --- | --- |
| `0059` | `0059_premium_abo_zustand.sql` | `0059_fahrtstatistiken_serverseitig_erzwingen.sql` — the A1 fix |
| `0060` | `0060_premium_funktionen_execute_entziehen.sql` | `0060_private_strecken_aus_oeffentlichen_views.sql` — the A3 fix |

`supabase_migrations.schema_migrations.version` is a primary key, so neither
outstanding file can ever be recorded under its own number: `supabase db push`
will skip both silently. `README.md:97-98` already notes both are merged to
`main` and unapplied, without connecting that to the collision.

Because neither file has been executed anywhere, Core Rule 9 does not apply to
them.

**Fix:** rename to `0070_`/`0071_`, correct the count in
`supabase/migrations/README.md` and `AGENTS.md`, and add a CI step that fails on
duplicate prefixes (the prior audit already flagged the missing migration lint).
Cost is near zero and it unblocks the two security migrations.

### N4 — `routes` is the only core table without grant hardening

`0001_init.sql:107-114`, `0033:5-16`

`grep -n "revoke.*routes"` across all 75 migrations returns **0 matches**, so
table grants sit at Supabase's default. The UPDATE policy has no `WITH CHECK`:

```sql
create policy "Nutzer können eigene unverifizierte Strecken bearbeiten"
  on public.routes for update
  using (erstellt_von = auth.uid() and status_ok = false);   -- no with check, all columns
```

`0033 A` derives `laenge_km` from `ST_Length()`, but only inside
`propose_route_full`. A direct `PATCH /rest/v1/routes` after the RPC sets
`laenge_km`, `geometry`, `start_coord`, `hoehe_m`, `tempolimits` and
`hoehenprofil` freely, and `laenge_km` feeds the kilometre leaderboard via
`coalesce(rc.distanz_km, r.laenge_km)` (`0060_private_strecken…:135`).

This is the same class `0046` closed for `route_completions` and `0034` for
`profiles`. `routes` was left out.

**Fix:** `REVOKE INSERT, UPDATE`, re-grant the descriptive columns only, and add
a BEFORE trigger deriving `laenge_km`/`start_coord`/`ziel_coord` from the
geometry. Keep `ist_privat` in the UPDATE grant or the premium private-route
feature breaks.

### N5 — Account deletion leaves the subscription row; the nightly cron re-grants premium

`0058_kontoloeschung_werte_nullen.sql:85-120` vs `0059_premium_abo_zustand.sql:236-254`

`anonymize_own_account()` clears the profile and sets `ist_premium = false`, but
never deletes from `subscriptions`. It is granted directly to `authenticated`,
so `POST /rest/v1/rpc/anonymize_own_account` bypasses both the password
re-authentication and the `kuendigeStripeAbo()` call that
`lib/actions/auth.ts:300-308` performs on the proper path — and that deletion is
itself gated behind `if (!profile?.stripe_customer_id) return true;` (`:273`).

`premium_abgleich()`, run by cron (`app/api/cron/premium-abgleich/route.ts:46`),
then reconciles `profiles.ist_premium` from `subscriptions.status`, flipping the
deleted account back to premium. Stripe keeps billing.

**Fix:** `create or replace anonymize_own_account()` with
`delete from public.subscriptions where user_id = auth.uid();`, and constrain
`premium_abgleich()` to `where p.geloescht_am is null`.
**Ordering caveat:** `0058` is not applied and depends on `0042`, which was
deliberately skipped, so `profiles.geloescht_am` does not exist in production. A
migration referencing it fails there. Sequence the column first. Cancelling the
Stripe subscription itself cannot be done from a migration.

### N6 — Guest ride handoff fails silently and starts a fresh recording

`components/useRideRecorder.ts:570`, `GefahrenSection.tsx:37`, `lib/trackingStorage.ts:124`

```ts
start(snapshot?.phase === "tracking" ? snapshot : undefined);
```

`adoptGuestTrackingSnapshot(...)`'s return value is never read. When adoption
fails — continuation token TTL is 2 h while the snapshot lives 24 h, or the
confirmation link is opened in a different browser, or localStorage is blocked —
`loadTrackingSnapshot` finds nothing and the hook calls `start(undefined)`.
`GefahrenSection` has already expanded because of the `?fortsetzen=` marker, so
the page requests GPS and begins a **new** ride. Someone who just signed up
specifically to save a 40 km ride lands in an empty recorder with no message.

This sits on the step-2→step-6 handoff of the core loop, where AGENTS.md asks
that transitions be checked explicitly.

**Fix:** return an adoption status; on failure do not `start()` — render an
explanation with a route back. Raise the token TTL to match the snapshot's 24 h.

### N7 — Moderator UPDATE policy has no `WITH CHECK`, so moderators can publish

`0046_fahrt_meldungen.sql:80-85`

```sql
create policy "Moderatoren können Fahrten entöffentlichen"
  on public.route_completions for update
  using (exists (select 1 from public.profiles
                 where id = (select auth.uid()) and is_moderator = true));
```

With no `WITH CHECK`, Postgres reuses `USING` as the check. That predicate tests
only the caller, never the row, so it is unconditionally true. Combined with
`grant update (ist_oeffentlich, notiz, track_oeffentlich)` (`:78`), a moderator
can flip any stranger's ride from private to **public**, overwrite the private
`notiz`, and set `track_oeffentlich`. For `art='frei'` the coverage trigger
returns early (`0052:172-174`) and does not intervene. The policy's own comment
claims the opposite ("Bewusst nur das und kein Löschen").

**Fix:** re-create with `with check (ist_oeffentlich = false and track_oeffentlich is null)`.
`lib/actions/moderation.ts:157-160` writes exactly that, so the only caller
stays valid.

### Security

- **Two undocumented service-role call sites.** `lib/storageUrls.ts:54` and
  `app/api/cron/premium-abgleich/route.ts:43`. `AGENTS.md`, `.agents/backend.md`
  and `lib/supabase/admin.ts:4-22` all describe two patterns across three files;
  there are five. Both new sites are absent from Protected Areas and CODEOWNERS,
  so the review checkpoint AGENTS.md prescribes for exactly this step was
  skipped twice. Both are correct today. The latent risk is
  `signiereFotoUrls(urls: string[])`, which has no authorization of its own —
  today's callers pass URLs from already-filtered views, but a future caller
  passing a `formData` value would mint signed links to any object in the
  `route-photos` bucket, undoing `0061`'s private-bucket work in one line.
- **Logout CSRF.** `app/auth/abmelden/route.ts:4-8` — a POST Route Handler with
  no CSRF token and no Origin/Referer check. Route Handlers get no built-in
  origin check. Limited damage, but it drops an in-progress recording out of the
  signed-in state.
- **`searchProfiles` is an unauthenticated, unthrottled Server Action.**
  `lib/actions/profile.ts:27-48` — exported from a `"use server"` file, no
  `getUser()`, no rate limit. The data is public under RLS, but it enables an
  unbounded `ilike '%…%'` sweep of the whole `display_name` set.
  `.agents/backend.md` requires the IP limiter for session-less endpoints.
- **Client-controlled file extension in storage keys.** `lib/actions/profile.ts:145`,
  `lib/actions/completions.ts:135` — `foto.name.split(".").pop()` is unfiltered
  and may contain slashes. Escape is **not** possible (storage policies pin
  segment 1 to `auth.uid()`), but it defeats `upsert: true` on avatars, leaving
  orphaned objects.
- **`foto.type` is the only server-side type check** (`profile.ts:142`,
  `completions.ts:128`); `startsWith("image/")` admits `image/svg+xml`. What
  actually stops stored XSS is the bucket `allowed_mime_types` in `0033:76-78` —
  so **confirm `0033` is applied in production**, because without it the app
  check is the only one and it does not hold.
- **Rate-limit key sharing.** All three public endpoints share
  `api:strecken:${ip}` at 60/min, and `GET /api/strecken` runs `getRoutes()`
  with `select("*")` and no caching. Combined with the known spoofable
  `x-forwarded-for` key and per-instance counters, that is a cheap database DoS
  lever.
- **No CSP or security headers** (known, §B). Two aspects not in the existing
  entry: `frame-ancestors` is missing on an app whose sign-in form is
  addressable via `?next=`, which compounds N1; and `Referrer-Policy` is missing
  while `app/fahrten/[id]` carries signed storage URLs with `?token=` in the DOM.

### Performance

- **`auth.getUser()` is not memoised.** Under `@supabase/ssr` this is a network
  call to GoTrue, not a cookie parse. On `/strecken/[id]` it runs four times per
  request (proxy → page → `getPremiumStatus` → `Header`). 60 call sites; only 4
  modules use `cache()`, and not this one. Largest single lever in the repo.
- **`<Header />` serialises three more roundtrips after the page's.** It is a
  child of the page, so its `getUser` → `isModerator` → `getUnseenKudosCount`
  chain runs *after* the page's own `Promise.all` blocks resolve. `grep Suspense`
  returns 0 matches app-wide.
- **`getRoutes()` uses `select("*")`** (`lib/routes.ts:8-14`), shipping geometry,
  `hoehenprofil`, `tempolimits` and `charakter_text` for every route into the RSC
  payload on `/` and on `/fahrten/neu` (where the comment says routes are for
  orientation only), and through the public API, which discards most of it.
  `listRouteChoices()` 20 lines below does it correctly.
- **N+1 inside a privacy boundary.** `lib/publicTrack.ts:78-86` updates one row
  per ride sequentially. A user with 200 shared rides changing their privacy
  radius triggers 200 sequential roundtrips in one Server Action; if it times out
  mid-way, the remaining tracks stay public at the **old, wider** radius. The
  comment at `:43-45` rules out a single SQL UPDATE, which does not rule out a
  batched upsert.
- **`revalidatePath("/fahrer/[id]", "page")`** in `lib/actions/kudos.ts:45-48`
  invalidates *every* rider and ride page platform-wide on every single kudo, and
  `revalidatePath("/profil")` targets the giver's page, which does not change.
  `lib/actions/follows.ts:41` does it correctly with a concrete path.
  *(Segment semantics to be confirmed against the Next 16 docs.)*
- `/strecken/[id]` blocks entirely on an Open-Meteo call inside its `Promise.all`
  (`page.tsx:85-103`); there is no `<Suspense>` anywhere and a single root
  `loading.tsx` shows an explore-shaped skeleton on `/profil`, `/feed`,
  `/leaderboards` and `/fahrten/[id]`.
- `/profil` and `/fahrer/[id]` load *all* rides with no `limit()`. Note the
  totals are computed in JS over the full list (`lib/profile.ts:80-95`), so a
  bare `limit()` would corrupt them — aggregates need to move to the DB first.
- Snapshotting remains O(n²) despite the 10 s throttle
  (`useRideRecorder.ts:195-199`): a 4 h ride at 1 Hz serialises roughly 600 MB
  cumulatively through synchronous main-thread `localStorage` writes, ending at
  ~800 KB per write.
- The photo lightbox uses a raw `<img>` on the original file
  (`PhotoGallery.tsx:117`) — up to 8 MB, given `bodySizeLimit: "9mb"`. Supabase
  image transformations are unused repo-wide.

## Confirmed sound (do not regress)

- The Stripe webhook: `constructEvent` before any payload access
  (`route.ts:134`), state re-fetched from Stripe rather than trusted
  (`:36`), idempotency via claim-before-process with an expiry and an atomic
  takeover UPDATE (`lib/stripeWebhook.ts:110-155`), 500 + release on error,
  503 on `in_arbeit`.

## Method and limits

Five agents, each restricted to reading, each given the 2026-09-06 remediation
table as an exclusion list. Database findings derive from migration files only —
no database was contacted, so nothing here establishes what the live schema
actually contains, and `supabase/migrations/README.md` documents that the two
have diverged before.

Lint, tests and build were not run (`node_modules/` is absent). Components and
`app/` routes have no automated coverage in this project at all, so every UI
finding is a reading of the source rather than an observed failure.

Highest-risk untested modules, in order: `lib/publicTrack.ts` (Protected Area,
privacy boundary, and the orchestrator above the well-tested `lib/track.ts`),
`lib/premiumLimits.ts` (money; pure functions whose values are quoted verbatim in
the terms), `lib/moderation.ts` (authorization; three near-identical
join-in-JS blocks), `lib/profile.ts` (seven `zeigt_*` opt-ins deciding what a
stranger sees).
